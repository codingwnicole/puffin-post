# Thread titles, names, and summaries — implementation note

I want Puffin to handle this automatically as far as it honestly can, **without using AI by default**. RP posts are already structured enough that we should be able to make the parsing logic much smarter first. The app should never confidently invent a muse name or overwrite wording someone deliberately fixed.

## What a completed thread card should know

- My character's name.
- The partner character name(s), when the post actually declares or strongly supports them.
- The partner blog as a tidy fallback when the muse cannot be identified.
- A stable premise from the starter/setup.
- A separate latest-reply preview, so I can see what changed without opening Tumblr.

The default label should become:

> `my muse × partner muse #3 — optional premise`

`#3` is the number of scenes I have tracked between that character and partner in this workspace. If we only know the blog, use the blog name without `.tumblr.com`; do not guess a muse name.

## Parsing rules, in confidence order

Read **both** the clicked post/reblog and the root starter, then use the best evidence from either. A reblog on my own blog may not contain the original header, so looking at only one is not enough.

1. The selected Puffin character is always my muse.
2. Look for explicit header formats first:
   - `who:` / `muses:` / `characters:` / `cast:`
   - `gifted for: dorian (@cursedsails)`
   - `closed starter for Rafaela (@blacktidesalt)`
   - `ft. cassian` / `featuring cassian`
   - compact headers like `dead man's bluff, kit & diana (@tidebovnd)`
3. Look for partner-side muse tags, such as `cassian threads`, `convo: kit & diana`, or `ship: x + y`.
4. Only then use a conservative prose check: a likely name should recur in the partner's prose and/or appear in my reply. One random capitalized word is not enough.
5. If there is still no safe muse result, display the partner blog. This is better than giving someone a fake character name.

The parser should return the result plus a source/confidence label internally. That makes debugging possible and lets the UI say what Puffin found instead of producing mystery output.

## Titles and premises need ownership rules

Puffin needs to distinguish its own generated values from mine. Add metadata for automatic vs user-edited title/premise values. Refreshing a Tumblr thread may update an automatic value; it must never overwrite a user-edited title or premise.

For existing rows, treat meaningful custom text as user-owned. Old generic titles such as `Tumblr thread` or `Tagged starter from ...` can be safely eligible for an automatic suggestion, but should not silently change until I choose to apply it or run a bulk refresh.

The UI should expose:

- **Refresh names & setup** — re-runs deterministic parsing.
- **Use Puffin’s suggestion** — applies a new title/premise only when I ask.
- **Edited by you** / **Generated by Puffin** — quiet provenance, useful when something looks wrong.

## Summary behavior

Do not pretend a regex can write a real plot synopsis from several long RP replies. The no-AI default should use two separate, genuinely useful pieces of content:

- **Premise:** setting/header plus the opening non-header sentences from the root starter. Stable and editable.
- **Latest preview:** a short excerpt from the most recent direct partner reply. This refreshes with activity and tells me what I am walking back into.

That is better than a fake “summary” that gets plot details wrong. A manually editable one-line recap remains available for people who want it.

An actual generated story recap can be considered later as an explicit, on-demand feature only. It should never be required for the inbox to work and should never run in the background on every thread refresh.

## Refresh behavior to fix

The current refresh path is too strict: it refuses to continue unless it finds declared names, even when the tag or prose parser found usable evidence. Refresh should accept any safe result from the priority list above, preserve user-owned fields, and report what it found.

Examples to cover before shipping:

- `gifted for: dorian (@cursedsails)`
- `@frgdust — ft. cassian`
- `closed starter for Rafaela (@blacktidesalt)`
- `dead man's bluff, kit & diana (@tidebovnd)`
- a reblog on my own blog where only the root has the RP header
- a headerless thread that correctly falls back to the partner blog

## Scope / non-goals for this pass

- No required AI provider, credits, or background model calls.
- No rewriting existing custom titles or premises.
- No forced name match when the source does not support one.
- Manual/Discord scenes remain manual-friendly; automatic parsing only runs when a supported post link exists.
